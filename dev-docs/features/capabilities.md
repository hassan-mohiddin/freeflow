# Capabilities

> **Covers:** `skills/setup-freeflow/scripts/capabilities.mjs`, `hooks/claude/freeflow.mjs`, `hooks/codex/driver.mjs`, `pi-extension/src/events/`
> **Verified at:** `c1702c8a` (2026-11-14)
> **User docs:** `plugin-docs/capabilities/event-log.md`

What Freeflow can do in a session, for the requests of request set 1 (pin, inject, forget, compact, checkpoint, rewind, route, spawn, send, wake, ask, block, sensors, timers). Each driver, Claude Code's mod, Pi's extension and Codex's driver, writes its claims at session start to `<FREEFLOW_HOME>/sessions/<session ID>/capabilities.json`: `yes` for what it carries out today, with a conformance test, `possible` for what the host offers and Freeflow does not use yet, `no` for what the host cannot do, each with how or why not. A user lists them with `/freeflow capabilities`; the agent with Setup Freeflow's `capabilities.mjs`, whose `check <request>` exits 0 only for `yes`. A host with no driver (Cursor, Copilot, Gemini) writes no file, and the script says that only the session-start guidance arrives there. Track Work's `checkpoint --compact` reads the same file and leaves a compaction request only where a driver claims `compact`. The last line of the listing names the session's event log.

## Sub-features

- `caps-no-driver`: with no claims for the session, `capabilities.mjs list` says no driver runs here, lists `inject` and `checkpoint` as yes and the rest as no, and no event log; `check compact` exits 1.
- `caps-claude-code`: on Claude Code, `/freeflow capabilities` lists the mod's claims for a headless run (`wake` no, `compact` only on the next compaction), with no model call.
- `caps-claude-code-pin`: on Claude Code, Freeflow's guidance is a section of the system prompt and its session-start hooks' copies are left out of the messages (`/context`), with no model call.
- `caps-pi`: on Pi, `/freeflow capabilities` lists the extension's claims and the event log, with no model call.
- `caps-compact-refused`: `checkpoint --compact` in a session with no claims writes the checkpoint and no request, and says so.
- `caps-sent`: `/freeflow sent` on Claude Code and Pi lists the text Freeflow sent the model in the session, newest first, and `/freeflow sent <n>` prints entry n whole; with the event log off it keeps and lists nothing. Covered by the test `the text Freeflow sent the model is kept whole: a notice and each gate row as a sent line; /freeflow sent lists it and shows one whole` in `hooks/claude/freeflow.test.ts` (`claude plugin test .`, no model call), and by Pi's recorder tests in `pi-extension/tests/events/recorder.test.js`; a live check on Pi needs a model call only for the notice and the gate, not for `/freeflow sent`.
- `caps-codex`: after Codex's driver ran its session start, `capabilities.mjs list` gives Codex's claims, and `checkpoint --compact` is refused naming what makes Codex compact.

## How to get to it (user POV)

- Run `/freeflow capabilities` on Claude Code or Pi; on Codex, ask the agent.
- Ask the agent what Freeflow can do here; it runs `node <setup-freeflow>/scripts/capabilities.mjs` (`list`, `check <request>`, `--json`).

## Driving it

Preconditions: a scratch folder holding a Git repository with `.freeflow/config.json` `{}`, and an empty folder for `FREEFLOW_HOME`. Every command below runs in the repository with `FREEFLOW_HOME` set to that folder; `<plugin>` is this checkout. No step calls a model.

- **No driver.** Run `FREEFLOW_SESSION=s-1 node <plugin>/skills/setup-freeflow/scripts/capabilities.mjs list`. Exit code `0`; the first line reads `No Freeflow driver runs in this session: only the session-start guidance arrives here, and the agent runs Freeflow's scripts itself.`, `inject` and `checkpoint` read `yes`, the other twelve `no` with `no Freeflow driver runs here`, and the last line is `Event log: none; no driver writes one here.` Then `FREEFLOW_SESSION=s-1 node <plugin>/skills/setup-freeflow/scripts/capabilities.mjs check compact; echo "exit $?"`: `compact: no (no driver): no Freeflow driver runs here` and `exit 1`.
- **Compaction refused.** In a store with a task this session holds (`node <plugin>/skills/track-work/scripts/working-record.mjs store init --git-name P --git-email p@example.com`, `project new --name widget`, `task create --title Probe --goal "Probe." --cue "read when probing" --project widget`, all with `FREEFLOW_SESSION=s-1`), run `FREEFLOW_SESSION=s-1 node <plugin>/skills/track-work/scripts/working-record.mjs checkpoint --record widget/task-001 --compact | tail -1`. Output `No Freeflow driver here compacts (no capabilities for this session). The harness compacts on its own; after it, recover with view recover.`; `test -e "$FREEFLOW_HOME/sessions/s-1/compact.json"; echo $?` prints `1`: no request was written.
- **Codex.** In a scratch folder with `FREEFLOW_HOME` set to `"$PWD/caps-home"` and `CODEX_HOME` to an empty folder, make a store with a task this session holds as in Compaction refused but with `FREEFLOW_SESSION=thr_c1 FREEFLOW_HARNESS=Codex`, then run Codex's session start as Codex does: `echo "{\"session_id\":\"thr_c1\",\"cwd\":\"$PWD\",\"hook_event_name\":\"SessionStart\",\"source\":\"startup\",\"model\":\"gpt-5-codex\",\"transcript_path\":null,\"permission_mode\":\"default\"}" | node <plugin>/hooks/codex/driver.mjs SessionStart >/dev/null`, then `FREEFLOW_SESSION=thr_c1 node <plugin>/skills/setup-freeflow/scripts/capabilities.mjs list`. Exit code `0`; the first line reads `Freeflow on Codex (codex-driver 0.9.0, request set 1)`; `pin`, `inject`, `checkpoint`, `block` and `sensors` read `yes`, `block` with `PreToolUse denies a gate's call under block (gates.*), with the reason; not hosted tools such as web search`, the other nine `no`; the last line reads `Event log: on,` the session's log and `(0 line(s))`. Then `FREEFLOW_SESSION=thr_c1 node <plugin>/skills/track-work/scripts/working-record.mjs checkpoint --record widget/task-001 --compact | tail -1` prints `Freeflow's driver here does not compact (compact: no, Codex compacts on its own (model_auto_compact_token_limit, model_post_turn_compact_threshold_percent or /compact); after it, the bundle is added). The harness compacts on its own; after it, recover with view recover.`
- **Claude Code.** With `CLAUDE_CODE_PLUGIN_DIRS` unset and `ANTHROPIC_BASE_URL=http://127.0.0.1:9`, so a model call would fail instead of being made, run `claude -p "/freeflow capabilities" --plugin-dir <plugin>`. Exit code `0`; the output starts `freeflow: Freeflow on Claude Code (claude-code-mod 0.9.0, request set 1, headless)`, lists the fourteen requests with `pin` (`its guidance is a section of the system prompt (prompt.compose)`), `inject`, `compact`, `checkpoint`, `send`, `block` (its how naming the gates, `gates.*`), `sensors` and `timers` as `yes`, `wake` as `no` with `nothing runs between turns in a headless run`, and `compact`'s line reads `on the next compaction; it cannot start one in a headless run`; the last line reads `Event log: on,` the session's `events/<session>.jsonl` under `FREEFLOW_HOME`, and its line count. `ls "$FREEFLOW_HOME"/sessions/*/capabilities.json` shows the file the mod wrote.
- **Claude Code's guidance pinned.** The same way, in the same repository, run `claude -p "/context" --plugin-dir <plugin> < /dev/null`. Exit code `0`; in the category table `System prompt` reads `7k` (`6.6k` in an earlier drive) and `Messages` a few hundred tokens at most (the store's menu, whose size depends on the store: 133 and 169 in two scratch stores): the core prompt, the Interaction Contract and the Working Method are in the system prompt, and the session start's context carries none of them. With the plugin at a commit before SPEC-013 the same command reads about `1.7k` and `5.1k`: the same text, in the messages. `cat "$FREEFLOW_HOME"/sessions/<session>/start.json` shows the session-start ledger: the six steps (`window`, `cycle`, `capabilities`, `sync`, `menu`, `guidance`) and `"pinned": true`.
- **Pi.** Run `scripts/verify-live.sh launch` (config `{}`), then `scripts/verify-live.sh cmd "/freeflow capabilities"`. The pane shows `Freeflow on Pi (pi-extension 0.9.0, request set 1, interactive)`, `pin`, `inject`, `compact`, `checkpoint`, `wake`, `ask`, `block`, `sensors` and `timers` as `yes`, `forget` and `route` as `possible` (Pi offers the calls; Freeflow does not use them), `send` as `possible` (Messaging is off), `rewind` and `spawn` as `no`, and `Event log: on,` the session's log under the run's Freeflow home. Then `scripts/verify-live.sh snap caps-pi`, and clean up.

## Gotchas

- `/freeflow capabilities` reads the claims file the driver wrote at session start; on Pi the command writes the current claims first, on Claude Code a settings change rewrites them.
- The line count of the event log counts lines already written: Claude Code writes a turn's lines at its end, and Pi once the session stays idle two seconds after a run, so a count right after a command may not include it.
- The session ID is `FREEFLOW_SESSION`, else `CLAUDE_CODE_SESSION_ID`, as Track Work reads it; a Pi run inside a Claude Code terminal passes its own with `--session`.
