# Track Work CLI

> **Covers:** `skills/track-work/scripts/`, `skills/discuss-work/scripts/choices.mjs`, `skills/discuss-work/scripts/lib/choices.mjs`, `skills/discuss-work/scripts/drift.mjs`
> **Verified at:** `e0e3133b` (2026-11-04)

On Claude Code, Codex and other hosts, Working Records are created and read through the Track Work CLI, `skills/track-work/scripts/working-record.mjs`. A user, or their agent under the Track Work skill, creates a task with a Goal, a next action and a cue: `init` writes a Schema 5 task folder, `view recover` prints what recovery reads, and `validate` checks it (structure, plus a warning for each pointer in a Slice's updates that does not resolve). A Schema 4 record, written by an earlier Freeflow in a repository or by Pi's former Task Memory, is read only by `migrate`: every other command refuses it and names `migrate`. The same CLI sets up the Freeflow store, one Git repository that holds every task's memory, local by default and a cloud store once the user adds a private remote: `store init` makes a local store, or with `--remote` clones the user's remote into the store's folder and, when it is empty, lays the store out and pushes its first commit; `store remote` turns a local store into a cloud store; `store status` says where it stands; `store sync` commits and, in a cloud store, takes the remote's commits and pushes. In the store, `project new` makes a project and `task create` a Schema 5 task (`record.md`, `history.md`, `decisions.md`, `sessions.md`) that the session holds; the agreement and slice commands keep it, closing a Slice appends its History entry, `checkpoint` writes where the work repository stands, `view recover` prints what recovery reads in order, a second session's `task take` is refused while another holds the task, `task here` prints the session-start menu for the folder's repository, and `task remove` deletes a task that Git history keeps. `delegate open` writes a delegation's brief and its worker's worktree, `delegate check-return` checks the return's shape and commits, `view recover --delegation` is the worker's recovery, and `delegate close` records the outcome in History; without `--agent`, `delegate open` takes the worker's model and effort from the routing table a new store's `rules/routing.md` holds, by the work's kind, `--settled` and `--check`, and a return sent back needs its `--reason`. `migrate` converts a Schema 4 record to Schema 5, in place or into the store; `discussion list`, `save` and `drop` keep the user's messages that shaped the work as blocks; `budget` prints the recovery budget for the session's context window before the agent writes, `task set-budget` switches a task to expanded mode, `checkpoint --input` rewrites In flight (leaving out a labelled line that says only `none`), and `view bundle` prints everything recovery reads, whole, with its sizes; without a task, `checkpoint --session` writes the session summary that `view bundle --session` prints. A task may belong to no project (`task create --no-project`, or when no project's tasks name the repository; ID `task-NNN`), and `task move` puts it into a project or takes it out; `estimate` gives the context's use against the window and the notice point, with a projection of the work left. The commands measure what each Slice uses and predict the next from it, `estimate --plan` lays the Slices left across context cycles, and Discuss Work's `choices.mjs agreement --plan` turns its `--json` into the agreement's Size line. The record format: Track Work's `skills/track-work/references/working-record-format.md` (Schema 5, the store and projects).

## Sub-features

- `tw-init`: `init` creates a Schema 5 `.freeflow/tasks/task-NNN-<short-name>/` task folder from Markdown fragments, in a repository where no `.freeflow/tasks/` exists yet, and prints the recovery budget.
- `tw-init5`: `init` without `--cue` is refused; with one it writes the next task folder.
- `tw-view`: `view recover` prints the opening line, the rules and the record.
- `tw-validate`: reports `valid` for a well-formed record.
- `tw-refuse`: refuses a task with no Goal, and a task folder Git does not ignore.
- `tw-schema4`: a Schema 4 record is refused by `view recover`, naming `migrate`, and printed whole by `view full`.
- `tw-store-local`: `store init` without `--remote` makes a local store, `store sync` commits there with nothing to push, and `store remote --url` makes it a cloud store with its history pushed.
- `tw-store-init`: `store init` against an empty remote writes `store.json`, `.gitignore`, `.gitattributes`, `rules/` and `projects/`, and pushes one commit authored as the user.
- `tw-store-sync`: `store status` counts what is not committed; `store sync` commits it and pushes.
- `tw-store-join`: `store init` from the same remote into another folder joins the store with no commit of its own.
- `tw-store-record`: a record inside the store passes the Git check, though Git tracks it.
- `tw-store-task-memory`: `store init` stops on a folder that holds Pi's former Task Memory (`registry.json`), and says to move its records in with `migrate`.
- `tw-store-adopt`: `store init --remote` in a folder that already holds an empty clone of that remote, as a cloud session has it, lays the store out there and pushes.
- `tw-store-offline`: with the remote out of reach, `store sync` commits, says it did not push and exits `0`; the next sync pushes.
- `tw-store-conflict`: a file both machines changed stops the sync with both copies kept, and `store sync --resolved` pushes the merged one.
- `tw-store-secret`: a planted key stops the push, named by path, line and kind; once removed, the push carries no commit that held it.
- `tw5-task`: `project new` and `task create` make a project and a Schema 5 task folder in the store, held by this session and pushed.
- `tw5-slice`: `agreement open`, `slice start-direct` and `slice close` keep the task; the close appends one History entry and pushes it.
- `tw5-recover`: `checkpoint` writes the work repository's Space line; `view recover` prints the opening line, rules, record, decisions, History and project indexes, then the checks with the hold.
- `tw5-hold`: a second session's `task take` is refused, naming the holder and its last sync; after a release it succeeds.
- `tw5-menu`: `task here` in the work repository lists its project's open tasks and says which one this session holds.
- `tw5-menu-store`: `task here` in the store's own folder lists every open task, and `--scan` finds the work repository for recovery.
- `tw5-take-back`: a session's end closes its hold as ended; that session's `checkpoint` is then refused, naming `task take`, and its resume (`task here --take-back`) takes the task back, saying so first.
- `tw5-no-push`: `task release --ended --no-push`, as Codex's driver closes a hold at a session's end, commits the release here only, and the next `store sync` pushes it.
- `tw5-remove`: `task remove` deletes the task in a pushed commit that Git history keeps.
- `tw5-delegate`: `delegate open` writes the brief, makes the worker's worktree on its own branch, and writes the delegation's line.
- `tw5-delegate-return`: `delegate check-return` refuses a missing return and passes a complete one; a sub-worker's delegation nests and a fourth level is refused; the worker's recovery leads with its brief.
- `tw5-delegate-close`: `delegate close` records the accepted outcome with its merge commit in one History entry and removes the line.
- `tw5-migrate`: `migrate` converts that Schema 4 record in place, keeps the old one whole in `sources/`, and the result validates.
- `tw5-migrate-recovery`: `migrate` converts a Schema 5 record written before the one Recovery list (Defined by, Read on recovery, Read when) in place, and the result validates.
- `tw5-migrate-store`: `migrate --project` brings a Schema 5 task kept in the repository into the store, unchanged.
- `tw5-discussion`: `discussion list` numbers the user's messages of a plain export, `save` keeps two as a block, the checkpoint lists the block once the work it shaped is closed, and `drop` removes it.
- `tw5-budget`: `budget` scales with the window the harness sets, `budget --record` shows what is left, and `task set-budget` switches the task to expanded mode.
- `tw5-bundle`: `checkpoint --input` rewrites In flight and, after a `Recovery:` line, the Recovery list, printing each line's size and share of the budget; `view bundle` prints every part in recovery's order, with a file cut to its lines numbered by line.
- `tw5-session`: without a task, `checkpoint --session` writes the session summary outside Git, and `view bundle --session` prints it.
- `tw5-session-recovery`: without a task, a session summary's Recovery always line naming a file is copied fresh, with its lines, into `view bundle --session`; a Recovery line with no class is refused.
- `tw5-session-status`: `session status` prints, as JSON for a harness layer, the task this session holds with its record and State as of, and whether the store has changes not yet synced.
- `tw5-missing`: where `FREEFLOW_HOME` names a folder with no store, `session status` says what is missing and who fixes it.
- `tw5-compact`: `checkpoint --compact` with no driver's claims for the session writes no request and says so; once a driver claims `compact`, it leaves the request for Freeflow's compaction that `session status` reports, which a harness layer answers once.
- `tw5-events`: `events append` writes a driver's lines with `seq`, redacts a token and refuses a line that is not schema v1; `events show` and `events summary` read them; a checkpoint commits the session's summary into the task folder.
- `tw5-fallback`: `view bundle --fallback` ends with the user's messages since the checkpoint, word for word, and a closing line naming the record's time and the transcript.
- `tw5-friction`: `checkpoint --input` leaves out a labelled line that says only `none`, and `validate` refuses a plain line under Future Work, naming the proposed Slice's shape.
- `tw5-loose`: `task create --no-project` makes a task in the store's `tasks/`, and `task move` puts it into a project with that project's next number, the hold following it.
- `tw5-estimate`: `estimate` gives the context's share and what is left before the notice, says whether the parts left fit or how many more context cycles they need, and without a measure asks for `--used`.
- `tw5-plan`: Slices measured with `--used` give the next Slice its `Predicted:` line; `estimate --plan` lays a list of Slices across context cycles from them, and its `--json` gives Discuss Work's agreement its Size line, last.
- `tw5-plan-model`: Slices measured from the transcript price the next Slice from those run on its model and effort, the transcript's newest request, once three were; on another model, from all of them, naming the model their cost was measured on.
- `tw5-sized`: Slices started with a Size and closed after a commit get Files, the files they added, changed or renamed; `estimate --plan` then predicts each Slice left from its size at their per-file rate, and leads with the range and what it rests on.
- `tw5-scratch`: with no task, `delegate open --scratch` writes a delegation's brief from the template under a scratch folder and records nothing, and `delegate check-return --scratch` checks its return.
- `tw5-space`: run from outside the work repository, the bundle reads a file the record names in a repository its Space lists, such as `AGENTS.md`, and its checks name an always Recovery line that points to no file.
- `tw5-rules`: `task here --rules` prints, after the menu, the store's rules and the rules of the folder's project, each whole: what Freeflow's harness layer gives a session at its start.
- `tw5-gates`: `session status` writes a session's gate state where none is; `agree` records a session's agreement and exact spec there and as an `agreement` event line, and is refused while a task is held; `agreement open`, `slice start-direct` and `task release` rewrite the state; `delegate open --writes` puts a `May write:` line in the brief's Scope, which the state reads.
- `tw5-pi`: `discussion list` reads a Pi session file along its active branch, leaving out a branch `/tree` left, and with no store `session status` still names the session (Pi's compaction through a session summary needs no store).
- `tw5-governor`: `events append` takes the cost governor's `governor` line and refuses one whose cap it does not know; `events summary` lists each response.
- `tw5-drift`: Discuss Work's `drift.mjs` lists the hunks of a change that no decision item's `Shows at` covers, and `choices.mjs return --base` prints their count.
- `tw5-route`: a new store's `rules/routing.md` holds the default routing table; `delegate open` without `--agent` takes the model and effort from its first matching row, prints the Route line and writes Route in the brief, with Settled and Check when given, refuses an Ask-first row and no match; `delegate close --outcome "sent back"` needs `--reason`, which History keeps; `estimate --plan` prints the sent-back rate by kind, check and model.

## How to get to it (user POV)

- Run `node skills/track-work/scripts/working-record.mjs --help` for the command list, and `<group> <operation> --help` before preparing input.
- On hosts other than Pi, the agent runs it for the user under the Track Work skill.
