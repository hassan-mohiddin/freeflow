# Review plan and review status

> **Covers:** `skills/review-work/scripts/review-plan.mjs`, `skills/review-work/scripts/review-status.mjs`, `skills/review-work/scripts/lib/plan.mjs`, `skills/review-work/scripts/lib/triggers.mjs`, `skills/review-work/scripts/lib/records.mjs`, `skills/review-work/scripts/check-adjudication.mjs`, `skills/deliver-work/scripts/delivery-state.mjs`
> **Verified at:** `HEAD` (2026-11-03)
> **User docs:** `plugin-docs/workflow.md`, `plugin-docs/settings.md`

Before work crosses its review unit (a pull request by default), the agent runs Review Work's `review-plan.mjs` and the user sees the plan in the agent's report: how deep the independent review goes (Quick, Standard or Deep), its tier, reviewers, rounds and humans, and why, computed from the diff, the `review.depth` policy in the base commit's `.freeflow/config.json`, the agreement's `Review:` lines and the built-in triggers. After the review is adjudicated, `check-adjudication.mjs --record` binds it to the commit it reviewed, and `review-status.mjs`, also printed by Deliver Work's `delivery-state.mjs`, says whether a review is on record for the head. Every command here reads files and Git only, with no model call. How it works: [Verification, review and evaluation](../subsystems/verification-review-evaluation.md#the-review-plan-and-the-review-record).

## Sub-features

- `plan-default`: a change no trigger or rule matches gets the default Standard plan, the same each run.
- `plan-builtins`: an auth path, a skill's description and a CI file fire their built-ins; a doc named for sessions and a skill body edit do not.
- `plan-base-policy`: a branch that edits the depth rules is planned with the base's rules; a base policy that does not validate refuses the plan.
- `plan-raise`: the agreement's `Review:` line and `--add` raise the plan; nothing removes a trigger.
- `status-record`: `review-status` and `delivery-state` say none, covered after a recorded adjudication, then stale with the re-review range.

## How to get to it (user POV)

- The agent runs `node <plugin>/skills/review-work/scripts/review-plan.mjs --base <ref> [--task <task folder>]` at the review unit, and `review-status.mjs` or `delivery-state.mjs --task <task folder> --base <ref>` before the unit's step; a user can run the same commands in a terminal.

## Driving it

Preconditions: `<plugin>` is this checkout, with `pi-extension/dist` built. A scratch folder `$R` holding a fresh Git repository on `main` (`git init -q -b main "$R"`) whose first commit has `README.md`, `src/app.js`, `skills/demo/SKILL.md` (front matter `name: demo` and `description: "Use when demoing."`, then a body) and `.freeflow/config.json` `{"review": {"depth": {"default": "standard", "rules": [{"paths": ["docs/**"], "depth": "quick"}]}}}`; and a task folder `$T` outside it with a `record.md` whose open agreement (`### Agreement A-001 — Demo`) has the lines `- Opened: 2026-11-03` and `- Done when it is done.`. Run every command in `$R` with `CLAUDE_CODE_SESSION_ID` and `FREEFLOW_SESSION` empty.

- **Default plan.** Run `git checkout -q -b change`, change `src/app.js`, commit, then `node <plugin>/skills/review-work/scripts/review-plan.mjs --base main`. Exit code `0`; the lines read `Review plan for 1 file, main (<8 hex>)..HEAD (<8 hex>)`, `  Unit: pr (the default)`, `  Depth: standard, tier standard, 1 reviewer, up to Review 2, humans 0`, `  Because: nothing matched; every file takes the default`, `  Default otherwise: standard`, `  Reviewer model: auto (the cheapest capable model, at a higher effort for this review)` and `  Already on record: none for <12 hex>`. Run it again with `--json` twice and compare: the two outputs are identical.
- **A docs-only change.** On a new branch from `main`, add `docs/guide.md` and commit; the plan's depth line reads `Depth: quick, tier standard, 1 reviewer, up to Review 2, humans 0`, with `rule 1 (.freeflow/config.json): docs/** -> quick` under Because.
- **Built-ins.** On a new branch from `main`, add `src/auth/login.js`, add `.github/workflows/ci.yml`, change the skill's description, add `src/sessions.md`, and commit. The plan reads `Depth: deep, tier security, 3 reviewers, up to Review 3, humans 0`, with `built-in "security": src/auth/login.js under auth/ -> deep`, `built-in "ci": .github/workflows/ci.yml a CI or release file -> deep` and `built-in "public interface": skills/demo/SKILL.md changes its description (by content) -> deep`; `sessions.md` is not named. On another branch, change only the skill's body: the plan is Standard with nothing matched.
- **The base's rules.** On a new branch from `main`, set `.freeflow/config.json` to `{"review": {"depth": {"default": "quick"}}}`, change `src/app.js`, and commit. The plan is still `Depth: standard`. Then commit `{"review": {"depth": {"default": "full"}}}` on `main` itself and plan that branch against it (`--base main`): exit code `2`, and stderr reads `review-plan: the base's .freeflow/config.json is invalid: review.depth.default must be one of quick, standard, deep; a broken policy never means no review`. Reset `main` to its first commit after (`git checkout -q main && git reset -q --hard HEAD~1`).
- **Raise the plan.** On the default plan's branch, add `- Review: src/app.js deep` to the agreement in `$T/record.md` and run the plan with `--task "$T"`: `Depth: deep`, with `the agreement: Review: src/app.js deep` under Because. Run it with `--add security --reason "it changes who may log in"`: `tier security`, with `security: added: it changes who may log in`. `--remove security` exits `2` with `Unknown option '--remove'`.
- **Status and record.** On the default plan's branch, run `node <plugin>/skills/review-work/scripts/review-status.mjs --task "$T" --base main`: exit code `1`, `Review: none for <head>; the plan says standard`. Run `node <plugin>/skills/review-work/scripts/review-packet.mjs --review 1 --base main --task "$T" --boundary "open the pull request"`: it writes `$T/reviews/R1-brief.md` with a `Plan: standard, tier standard, 1 reviewer, up to Review 2, model auto (…)` line and ends `check-brief: passes. Dispatch this brief.` Write `$T/reviews/R1-report.md` with `### Review Items`, `#### Issues — Non-blocking`, `N1. A name is unclear.`, then `## Adjudication`, `- N1: Accepted. Renamed.` and `Adjudicated judgment: Non-blocking`, and run `node <plugin>/skills/review-work/scripts/check-adjudication.mjs "$T/reviews/R1-report.md" --record`: `Adjudication complete`, and `Recorded in $T/reviews/records.jsonl: standard review of <head>, Non-blocking`. `review-status.mjs --task "$T"` now exits `0` with `Review: on record for <head> (standard, Non-blocking after Review 1)`, and `node <plugin>/skills/deliver-work/scripts/delivery-state.mjs --task "$T"` prints the same line after the Changelog line. Commit one more change: both read `Review: on record for <old head>; 1 commit since: a diff-only re-review covers <old head>..<new head>`.
- **A contradicted judgment.** Change the report's adjudication to `Adjudicated judgment: Pass` with a `#### Issues — Blocking` item `B1. It crashes.` disposed `- B1: Accepted. Reproduced.`: `check-adjudication.mjs` exits `1` with `- judgment: is Pass, but B1 is an Accepted Blocking Issue: the judgment is Blocking`, and `--record` writes nothing.

## Gotchas

- The plan reads the policy from `--base`'s commit, never the working tree: an uncommitted edit to `.freeflow/config.json` changes nothing until it is on the base.
- A `CLAUDE_CODE_SESSION_ID` or `FREEFLOW_SESSION` in the environment adds that session's settings to the plan and, without `--task`, points `review-status` at that session's `reviews/` in the Freeflow home; empty them for these steps.
- Short hashes differ in every run: match the shape (`<8 hex>`, `<12 hex>`), not the value.
