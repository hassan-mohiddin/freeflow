# Review plan and review status

> **Covers:** `skills/review-work/scripts/review-plan.mjs`, `skills/review-work/scripts/review-status.mjs`, `skills/review-work/scripts/lib/plan.mjs`, `skills/review-work/scripts/lib/triggers.mjs`, `skills/review-work/scripts/lib/records.mjs`, `skills/review-work/scripts/lib/review-rules.mjs`, `skills/review-work/scripts/check-adjudication.mjs`, `skills/deliver-work/scripts/delivery-state.mjs`
> **Verified at:** `0d98b19f` (2026-11-14: every step driven on D-054's change, uncommitted over this commit)
> **User docs:** `plugin-docs/workflow.md`, `plugin-docs/settings.md`

Review has no settings. Before a pull request opens, and before a push or a commit when the review rules say so, the agent runs Review Work's `review-status.mjs` (or Deliver Work's `delivery-state.mjs`, which prints the same lines) and the user sees in its report when a review is due and where that rule comes from: the project's `Review at:` line, else the user's `rules/review.md` in the Freeflow home, else Freeflow's default, every pull request. When one is due and none is on record, `review-plan.mjs` prints the floor every change gets, one reviewer and one round, and the flags the diff raises, each with its reason; above the floor is the agent's proposal to the user. After the review is adjudicated, `check-adjudication.mjs --record` binds it to the commit it reviewed. Every command here reads files and Git only, with no model call. How it works: [Verification, review and evaluation](../subsystems/verification-review-evaluation.md#the-review-plan-and-the-review-record).

## Sub-features

- `plan-floor`: a change no flag fires gets the floor, one reviewer and one round, the same each run.
- `plan-flags`: an auth path, a permission decision, a skill's description and a CI file raise their flags with the reason, and the floor stays; a doc named for sessions and a skill body edit raise none.
- `rules-layers`: a project's `Review at: push`, read at the base, wins over the home's `rules/review.md` and the default; a line that names no step is ignored and named; an old `review` block in `.freeflow/config.json` changes nothing.
- `plan-add`: the agreement's `Review:` line and `--add` raise a flag; nothing removes one.
- `status-record`: `review-status` and `delivery-state` say none, covered after a recorded adjudication, then stale with the re-review range, and with `--step` whether that step needs a review.
- `fixes-checked`: after a Blocking floor review whose Blocking items were accepted, the initiator's recorded check of the fixes covers the commit that holds them.

## How to get to it (user POV)

- The agent runs `node <plugin>/skills/review-work/scripts/review-status.mjs --base <ref> --step <commit|push|pull-request> [--task <task folder>]` (or `delivery-state.mjs` with the same options) before the step, and `review-plan.mjs --base <ref> [--task <task folder>]` when a review is due; a user can run the same commands in a terminal.

## Driving it

Preconditions: `<plugin>` is this checkout. A scratch folder `$R` holding a fresh Git repository on `main` (`git init -q -b main "$R"`) whose first commit has `README.md`, `src/app.js`, `src/hooks.js` (`export const check = () => ({});`) and `kit/demo/SKILL.md` (front matter `name: demo` and `description: "Use when demoing."`, then a body); a task folder `$T` outside it with a `record.md` whose open agreement (`### Agreement A-001 — Demo`) has the lines `- Opened: 2026-11-03` and `- Done when it is done.`; and an empty folder `$H`. Run every command in `$R` with `CLAUDE_CODE_SESSION_ID` and `FREEFLOW_SESSION` empty and `FREEFLOW_HOME=$H`.

- **The floor.** Run `git checkout -q -b change`, change `src/app.js`, commit, then `node <plugin>/skills/review-work/scripts/review-plan.mjs --base main`. Exit code `0`; the lines read `Review plan for 1 file, main (<8 hex>)..HEAD (<8 hex>)`, `  Review at: pull request (Freeflow's default)`, `  Floor: 1 reviewer, 1 round (Review 1); after it you check the fixes, with no second round by rule`, `  Flags: none`, `  Reviewer model: the routing table's review row (delegate open --kind review)` and `  Already on record: none for <12 hex>`. Run it again with `--json` twice and compare: the two outputs are identical.
- **Flags.** On a new branch from `main`, add `src/auth/login.js`, set `src/hooks.js` to `export const check = () => ({ decision: "deny" });`, add `.github/workflows/ci.yml`, change the skill's description, add `src/sessions.md`, and commit. The plan still reads `  Floor: 1 reviewer, 1 round (Review 1); …`, then `  Flags (each a reason to weigh more than the floor with the user; none changes it):`, with `    - security: src/auth/login.js under auth/; src/hooks.js changes a permission decision (by content)`, `    - ci: .github/workflows/ci.yml a CI or release file` and `    - public interface: kit/demo/SKILL.md changes its description (by content)`, then `  Above the floor: your call with the user: more reviewers, each with a different lens, or a stronger model; propose it with the reason and the cost`; `sessions.md` is not named. On another branch, change only the skill's body: `Flags: none`.
- **The rule's layers.** Write `$H/rules/review.md` with the line `Review at: commit`. On the floor's branch, `review-status.mjs --step push` prints `Review at: commit ($H/rules/review.md)` and `This step (push): a review is due`, exit code `1`. On `main`, commit `dev-docs/README.md` with a `## Review Rules` section holding `- Review at: push`, then on a new branch from it change `src/app.js` and commit: `review-status.mjs --base main --step commit` prints `Review at: push (dev-docs/README.md#review-rules at main)` and `This step (commit): no review is due (one is due at: push, pull request)`, exit code `0`; with `--step pull-request` it prints `This step (pull request): a review is due`, exit code `1`. Change the line on `main` to `- Review at: sometimes` and commit: the same command prints `Review at: commit ($H/rules/review.md)` and `  Ignored: dev-docs/README.md#review-rules "- Review at: sometimes": takes commit, push, pull request, not "sometimes"`. Then commit `.freeflow/config.json` `{"review": {"unit": "manual", "depth": {"default": "full"}}}` on the branch: `review-plan.mjs --base main` still exits `0` with the floor. Reset `main` to its first commit after (`git checkout -q main && git reset -q --hard <first commit>`) and remove `$H/rules`.
- **Add a flag.** On the floor's branch, add `- Review: src/app.js` to the agreement in `$T/record.md` and run the plan with `--task "$T"`: `    - the agreement: Review: src/app.js` under Flags, and the floor unchanged. Run it with `--add security --reason "it changes who may log in"`: `    - security (added): added: it changes who may log in`. `--remove security` exits `2` with `Unknown option '--remove'`.
- **Status and record.** On the floor's branch, run `node <plugin>/skills/review-work/scripts/review-status.mjs --task "$T" --base main`: exit code `1`, `Review: none for <head>; the floor: 1 reviewer, 1 round; flags: the agreement`, then `Review at: pull request (Freeflow's default)`. Run `node <plugin>/skills/review-work/scripts/review-packet.mjs --review 1 --base main --task "$T" --boundary "open the pull request"`: it writes `$T/reviews/R1-brief.md` with a `Plan: 1 reviewer, Review 1, the floor; flags: the agreement` line and ends `check-brief: passes. Dispatch this brief.` Write `$T/reviews/R1-report.md` with `### Review Items`, `#### Issues — Non-blocking`, `N1. A name is unclear.`, then `## Adjudication`, `- N1: Accepted. Renamed.` and `Adjudicated judgment: Non-blocking`, and run `node <plugin>/skills/review-work/scripts/check-adjudication.mjs "$T/reviews/R1-report.md" --record`: exit code `2`, `--record needs --model <name>, the reviewer's model, …`. Run it again with `--model test/reviewer`: `Adjudication complete`, and `Recorded in $T/reviews/records.jsonl: Review 1 of <head>, Non-blocking`. `review-status.mjs --task "$T"` now exits `0` with `Review: on record for <head> (Non-blocking after Review 1)`, and `node <plugin>/skills/deliver-work/scripts/delivery-state.mjs --task "$T" --step pull-request` prints the same line after the Changelog line, then `Review at: pull request (Freeflow's default)` and `This step (pull request): a review is due, and one is on record`. Commit one more change: both read `Review: on record for <old head>; 1 commit since: a diff-only re-review covers <old head>..<new head>`.
- **Checked fixes.** On a new branch from `main`, change `src/app.js`, commit, and write `$T/reviews/R2-brief.md` with `review-packet.mjs --review 1 --base main --task "$T" --boundary "open the pull request"`. Write `$T/reviews/R2-report.md` with `#### Issues — Blocking`, `B1. It crashes.`, then `## Adjudication`, `- B1: Accepted. Reproduced.` and `Adjudicated judgment: Blocking`, and record it with `check-adjudication.mjs "$T/reviews/R2-report.md" --record --model test/reviewer`: `review-status.mjs --task "$T"` exits `1`, `Review: none for <head>; the review of <head> on record is Blocking, which covers nothing`. Commit a fix, then run the same `check-adjudication.mjs` with `--fixed HEAD`: `Recorded in $T/reviews/records.jsonl: the fixes of Review 1 of <old head> (Blocking) checked at <new head>`, and `review-status.mjs --task "$T"` exits `0` with `Review: on record for <new head> (Review 1 of <old head> was Blocking; its fixes checked at <new head>)`.
- **A contradicted judgment.** Change the report's adjudication to `Adjudicated judgment: Pass` with a `#### Issues — Blocking` item `B1. It crashes.` disposed `- B1: Accepted. Reproduced.`: `check-adjudication.mjs` exits `1` with `- judgment: is Pass, but B1 is an Accepted Blocking Issue: the judgment is Blocking`, and `--record --model test/reviewer` writes nothing.

## Gotchas

- The project's rule is read from `--base`'s commit, or without `--base` from the head's merge-base with the default branch (origin's HEAD, else `main`), never from the change or the working tree: an edit to the Review Rules on a branch changes nothing until it is on the base.
- `FREEFLOW_HOME` decides the home's `rules/review.md`; one left pointing at a real home brings that user's rule into the steps. A `CLAUDE_CODE_SESSION_ID` or `FREEFLOW_SESSION` points `review-status` without `--task` at that session's `reviews/`; empty them for these steps.
- Short hashes differ in every run: match the shape (`<8 hex>`, `<12 hex>`), not the value.
