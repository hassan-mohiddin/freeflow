# Reference Pointers

> **Covers:** `hooks/shared/pointers.mjs`, `pi-extension/src/host/pointers.ts`, `skills/verify-work/scripts/lib/test-patterns.mjs`
> **Verified at:** `d664221e` (2026-11-18: the Codex steps, Claude Code's listing and change, and Pi's Pointers row in all three tabs driven at `d664221e` with model calls blocked; a pointer in a live Claude Code or Pi conversation is unverified, since it needs a model's tool call)
> **User docs:** `plugin-docs/settings.md`

The agent gets one line from a skill at the moment that skill's method matters, at most once per context cycle, after what it already received: a worker about to start (Execute Work's delegation reference), a pull request about to open (Deliver Work's Review Check), a test file edited (Verify Work's test design), and the same test command failing a second time (Execute Work's diagnose lines). Each line is kept as a `pointer` sent line, so `/freeflow sent` lists it. One Developer setting, Pointers (`pointers.enabled`, on by default), turns all four off. On Pi only the pull request and test edit pointers come from here: Pi has no workers, and Tool Execution's guidance notices send the diagnose lines (Pointers off holds those back too). How it works: the developer docs' Reference Pointers section.

## Sub-features

- `pointers-codex`: Codex's driver adds each pointer as hook context at its moment, once a cycle; a worker's start leaves its pointer for the next hook that can add context; each is a `pointer` sent line.
- `pointers-off`: with `pointers.enabled` off, no host sends one and none is logged.
- `pointers-setting`: the Pointers row in Claude Code's Developer settings and on Pi's screen in Session, This folder and Everywhere, with a harness tick.
- `pointers-claude-code`: Claude Code's mod appends each pointer as a row in the main conversation (driven in the mocked engine only).
- `pointers-pi`: Pi adds the pull request and test edit pointers to that call's result (driven in a native test only).

## How to get to it (user POV)

- Work as usual: the pointers come on their own. `/freeflow sent` (Claude Code and Pi) or `events sent --what pointer` lists those sent.
- Turn them off with `/freeflow settings pointers.enabled off` on Claude Code, the Pointers row of `/freeflow settings` on Pi, or `settings.mjs set pointers.enabled off`.

## Gotchas

- A pointer comes once per context cycle: a compaction, or a new session start on Claude Code and Codex, lets it come again; on Claude Code a reload of the mod does too.
- Only the main conversation gets pointers on Claude Code and Codex; a worker's own calls raise none.
- On Pi the pull request pointer joins the result of the `gh pr create` call, since Pi's path for a mid-turn line is the tool result.
- Codex's driver reads a test command's failure from its output text (`Exit code: N`, `Process exited with code N`), since Codex's hook input documents no exit code; a live Codex's output format is not driven here.
