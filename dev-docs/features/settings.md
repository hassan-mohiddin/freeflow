# Settings

> **Covers:** `pi-extension/src/host/settings/`, `pi-extension/src/host/config-validation.ts`, `pi-extension/src/host/config-store.ts`, `skills/setup-freeflow/scripts/settings.mjs`, `hooks/claude/freeflow.mjs`, `pi-extension/src/tool-execution/config.ts`, `pi-extension/src/compaction/config.ts`, `pi-extension/src/messaging/config.ts`
> **Verified at:** `f267f450` (2026-11-14): not driven in round 2: its steps' outputs did not change; the Session scope's removed-key naming (sessionProblems) is covered by `settings.test.mjs`
> **User docs:** `plugin-docs/settings.md`

`/freeflow settings` opens one screen with three scopes: Session (this Pi session only), Personal (`.freeflow/local.json`) and Repository (`.freeflow/config.json`). Changing a row writes that scope's file at once (Session writes none), and a capability switch reloads the Pi session when the screen closes, so the new skills and tools take effect. Which layer wins and why: the overview's [Cross-Cutting Concerns](../README.md#cross-cutting-concerns); the screen's code: `pi-extension/src/host/settings/README.md`.

Every key is one row of the settings table, `SETTINGS` in `config-validation.ts`: the validators, Pi's Session keys, the screen's writes, the settings script and the settings tests read it. A setting a user changes also gets a row on this screen, in all three scopes. A key with no row needs the user's agreement and its reason in the settings test's `FILE_ONLY` list (today only `review.depth`, the repository's review policy, which Review Work's plan reads from the base commit; SPEC-007), unless only Claude Code's mod acts on it (`hosts: "claude-code"`, the pane's `pane.enabled` and `pane.statusLine`), whose row is Claude Code's `/freeflow settings`; the test fails on a config key with no table row, no screen row, or a scope missing. That is why this file covers each capability's `config.ts` and the config validator: a new key flags it.

Outside Pi the same settings are changed by Setup Freeflow's script, `skills/setup-freeflow/scripts/settings.mjs`, which writes through the screen's own code (`config-store.ts`) and keeps a Session value in `<FREEFLOW_HOME>/sessions/<session ID>/settings.json`, read by the session-start hook. On Claude Code the mod serves `/freeflow settings` by running that script, and does nothing else while `enabled` is off (SPEC-005, in task-001's folder of the store). A key a file ignores (unknown, removed, or wrong for a known key) keeps its default: the script's `list` names it under the rows, and every host's status says so (D-045). A write to a file with ignored settings is refused, since writing would drop them; `settings.mjs doctor` prints each problem with its fix, changes nothing without `--fix`, and with `--fix` writes Personal and Session, and the Repository file only with `--scope repository`.

## Sub-features

- `settings-open`: opens the screen on the requested scope, without writing anything.
- `settings-repo-toggle`: switches a capability in the Repository scope and writes `.freeflow/config.json`.
- `settings-effect`: after closing, the session reloads and `/freeflow status` shows the change.
- `settings-personal-toggle`: cycles inherited, on and off in the Personal scope, writing `.freeflow/local.json` and removing it when nothing is left.
- `settings-personal-exclude`: when nothing ignores `.freeflow/local.json`, the first Personal write adds it to `.git/info/exclude`.
- `settings-session-toggle`: changes a Session value without touching either file.
- `settings-review`: the Review row cycles Review Work's unit in every scope, writing `review.unit` in a file scope, and its default leaves the file clean; Review rounds writes `review.rounds` as a number.
- `settings-reviewer-model`: the Reviewer model row opens a picker of the authenticated models, with inherit (Personal) or auto (Repository) first.
- `settings-guidance-notices`: the Guidance notices row under Tool Execution switches `toolExecution.guidanceNotices` in every scope.
- `settings-skills`: Skills is a switch for every skill but Setup Freeflow, and Each skill under it opens one switch per skill; an off skill is not loaded after the reload, and Each skill names it (`all but write skill`).
- `settings-prompts`: Runtime prompts is a switch for all three prompts, and Each prompt under it opens a switch for Core, the Interaction Contract and the Working Method; with them off, Freeflow stays active.
- `settings-gates`: the Gates row sets the delegation gate (`gates.delegation`) to `off`, `warn` or `block` in every scope; driven in [Gates](gates.md).
- `settings-all-scopes`: every setting has a row in Session, Personal and Repository; the test `every config key Freeflow acts on has a /freeflow settings row, or a stated reason it has none` checks it, nested screens included.
- `settings-script`: the settings script lists, sets and unsets a key in each scope with the screen's write rules, refuses a value the table does not allow, and prints the Runtime State line a change gave.
- `settings-removed-keys`: the removed keys `gates.agreement`, `gates.slice`, `gates.delivery` and `governor.cap` (with `governor.mode`) load from a file, are named as ignored with their reason by `list` and `doctor`, and `doctor --fix` removes them; `set` refuses them as unknown (D-058).
- `settings-claude-code`: on Claude Code, `/freeflow settings` lists the settings Claude Code acts on and changes one, the model reading the changed line in the running session, with no model call for the command itself.
- `settings-ignored`: a setting a file ignores keeps its default and is named by the script's list, the Pi footer and status, and Claude Code's listing; a write to that file is refused and names the doctor.
- `settings-setup-needed`: with no `.freeflow/config.json`, `/freeflow settings` refuses, naming `/setup-freeflow`, and writes nothing; a write from the script creates the file (D-045, round 3).
- `settings-doctor`: `settings.mjs doctor` prints each problem in each scope with its fix (a renamed key, a dropped key, a value reset to the default, a file that is not JSON left alone), changes nothing without `--fix`, writes Personal and Session with `--fix`, and writes the Repository file only with `--scope repository`.

## How to get to it (user POV)

- Run `/freeflow settings` (opens Personal), or `/freeflow settings session`, `/freeflow settings personal` (or `local`), `/freeflow settings repo` (or `repository`).
- Press `Tab` inside the screen to switch scope, `↑`/`↓` to move, `Enter` or `Space` to change a row, `Esc` to close.

## Gotchas

- `Enter` on the first row switches Freeflow itself for that scope. Always confirm the `›` row in the printed pane before `Enter`, and never press `Enter` just after `cmd` opens the screen.
- In the Repository scope `Enter` flips between on and off; in Personal and Session it cycles inherited, on and off.
- A capability switch reloads the session after `Esc`. Wait for the `Reloaded …` notice before the next command.
- The fixture's `.gitignore` already ignores `.freeflow/local.json`, so `.git/info/exclude` is written only after the **Personal exclude** step removes that rule.
- The list scrolls past 18 rows, so a row far from the cursor is off screen until the cursor nears it; every scope fits today. Match a row by its label and value, not by its spacing.
