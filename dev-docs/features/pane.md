# Pane and status line

> **Covers:** `hooks/claude/pane.mjs`, `hooks/claude/types.d.ts`
> **Verified at:** `bc6c443c` (2026-11-14)
> **User docs:** `plugin-docs/capabilities/pane.md`

On Claude Code, Freeflow's mod pins a status line under the prompt (`Freeflow › <project> › <task> · <agreement> · ctx N% (cycle N) · 7d N%`, the project's words within 16 characters and the task's within 24, or `Freeflow: no task held`) and opens one pane with `/freeflow pane`, laid out as layout B from the mock-ups Hassan chose on 2026-11-14: Needs you and Now fixed at the top, then five tabs switched by `1` to `5` (Projects and tasks, Workers, Sent, Settings, About). It asks for 50 columns docked and 24 rows inline; the terminal seats it. It is drawn from the scripts' JSON (`session status`, `project list --json`, `delegate status --json`, `estimate --spent --json`, `events summary --json`, `events sent --json`, the settings script's list). Its letter keys run Track Work's own commands (take, release, switch, create, check-return), stop a worker after asking, and change a setting through `/freeflow settings`; each that ran appends one row. `pane.enabled` and `pane.statusLine` turn them off. A `-p` run and a cloud session draw nothing.

## Sub-features

- `pane-mocked`: the mocked engine opens the pane, draws layout B at 50 columns and inline from fixture JSON, runs each tab's actions (take, take after asking, release, switch at once and after the checkpoint, new task; brief, return, see now, check, stop after asking; show older and a sent text; a setting's switch, choice and reach; the guide), cuts the status line's words, and draws without writing state.
- `pane-json`: the JSON outputs the pane reads, in a scratch store, with `events sent --json --limit` and `events summary`'s `agents`.
- `pane-headless`: `/freeflow pane` in a `-p` run says no surface is attached.
- `pane-settings`: `/freeflow settings` lists Pane and Status line, `pane.enabled off` makes `/freeflow pane` refuse, and `inherit` returns it.
- `pane-terminal`: in an interactive terminal session, the status line shows and `/freeflow pane` docks the pane beside the transcript, or opens it inline in a narrower terminal.

## How to get to it (user POV)

- Type `/freeflow pane` on Claude Code (terminal or the Desktop app's Code tab); press `1` to `5` while it has the focus, Enter on a row to pick it, and the letter keys shown under the picked row.
- Read the status line under the prompt.
- Turn either off with `/freeflow settings pane.enabled off` or `/freeflow settings pane.statusLine off`, or with their rows in the pane's Settings tab.

## Driving it

Preconditions: a scratch folder holding a Git repository `repo` with `.freeflow/config.json` `{}` and a remote `https://github.com/acme/widget.git`, and an empty folder `home` for `FREEFLOW_HOME`; `<plugin>` is this checkout; `W=<plugin>/skills/track-work/scripts/working-record.mjs`. Claude Code runs with `CLAUDE_CODE_PLUGIN_DIRS` and `FREEFLOW_SESSION` unset and `ANTHROPIC_BASE_URL=http://127.0.0.1:9`, so a model call would fail instead of being made. No step calls a model.

- **Mocked engine.** In `<plugin>`, run `claude plugin test .`. The twelve tests of `hooks/claude/pane.test.ts` pass with the mod's own: `/freeflow pane opens at 50 columns docked and 24 rows inline…`, `layout B: Needs you first, then Now, then the five tabs…`, `below about 112 columns the terminal seats the pane inline…`, `Projects and tasks: pick a project, pick a task, take, release, switch…`, `Workers: each delegation with model, effort, minutes and tokens…`, `Sent: the 20 newest lines, then show older…`, `Settings: the rows as switches and choices with a ⋯ reach menu…`, `About: the version, what is on, the guide`, `the status line's words…`, `the status line matches the fixture, has no workers…`, `no render writes state…`, `where no surface draws, or with the pane off, nothing is read for it`.

## Gotchas

- A session whose event log has no line yet has no `events summary` and no `events sent`; the pane takes that as no figures and an empty Sent, not a failure.
- The pane reads after the hook that asks has returned (`$.clock.after(0)`), so a test advances the mocked clock before it looks.
- `$.ui.ask` (take over, stop) is a tool call of `AskUserQuestion`; the tests answer it with a `tool.call` hook that returns `answers` keyed by the question.
- A plugin's own `$.command.run` skips its own hooks, so the pane cannot run `/freeflow settings` through the engine: it calls the mod's exported `settingsCommand` and appends the lines the command gives the model as one row.
- The terminal docks a pane in its full-screen layout from 110 columns; between 110 and 111 the dock is 49 columns, not 50. The mod cannot choose the seat: it asks for `columns` 50 and `rows` 24, and the surface decides.
- Where an installed Freeflow plugin is also present, `claude -p … --plugin-dir <plugin>` may print `freeflow: hooks module not loaded: another plugin of that name loads first`; the checkout's module answered the steps above all the same.
- The status line's ctx and 7d parts appear only after the session's first model request; before it the engine has no figures.
