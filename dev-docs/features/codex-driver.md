# Codex driver

> **Covers:** `hooks/codex/`
> **Verified at:** `f1f29ece` (2026-11-07)
> **User docs:** `plugin-docs/getting-started.md`, `plugin-docs/capabilities/event-log.md`

On Codex, Freeflow's driver runs on Codex's hook events once the user has approved its hooks in `/hooks`. At a session's start the agent gets Freeflow's guidance and, with a store, the task menu with the user's rules; as the context fills, a row at 50, 60 and 70 percent of the window and, near Codex's own compaction, one checkpoint notice, each after the next tool call or prompt; after Codex compacts, the task's record after Codex's summary. The event log keeps each loop event, written at the turn's end, the store syncs at a turn's end, and the session's end releases its hold, pushed at the next start. `capabilities.mjs` lists Codex's claims.

## Sub-features

- `codex-start`: session start gives the guidance, then the task menu saying which task this session holds, and writes Codex's claims.
- `codex-rows`: a model request past 50 percent of the window puts one row in the context at the next tool call; past the notice point, the notice naming the task comes at the next prompt.
- `codex-compact`: after Codex compacts, the guidance and the task's record follow, as of its last checkpoint and saying what it lacks when the checkpoint came first.
- `codex-log`: the turn's end writes the session's lines to the event log in one run, never contents.
- `codex-end`: the session's end releases the hold as ended, committed here only, and a resume takes the task back.

## How to get to it (user POV)

- Install Freeflow on Codex, approve its hooks in `/hooks`, and start a session in a repository with `.freeflow/config.json`.
- Ask the agent what Freeflow can do here; it runs `capabilities.mjs list`.

## Gotchas

- Each step runs the driver as its own process, as Codex does; what lasts between events is in `codex-home/sessions/thr_f1/`. Driving a step out of order leaves that state where the earlier step would have left it.
- The rows need a store and a window: with no store, or a model whose window the driver does not know and no `model_context_window` in Codex's config, no row or notice comes.
- The steps set `CODEX_HOME` to an empty folder so a real `~/.codex/config.toml` cannot change the window.
