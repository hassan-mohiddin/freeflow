For anyone changing how Track Work's script keeps task memory: the Freeflow store, the Schema 5 task folder, the commands that change it, the views recovery reads, delegation, and the measurement and planning built on them. The skill that teaches the agent when to use these is [Track Work](../skills/track-work.md); Pi's layer and Claude Code's mod, which call this script at the right moments, are in [Compaction](compaction.md#the-store-layer) and the [overview](../README.md).

## Purpose

An agent working for days, across many compactions, sessions and machines, needs memory that outlives every one of them, stays current and stays small enough to read back. The store and Schema 5 give it that: every task's memory in one private Git repository that syncs itself, a task folder whose state is rewritten and whose logs are appended, and a script that makes every lifecycle change, so the agent edits only meaning.

It replaces, for every harness, Schema 4's single growing `record.md`, Pi's registry of projects and child records, and the rule against opening a record. It does not decide what is worth recording (the skill does), it never authorizes work (the record is memory, not authority), and it writes nothing into a code repository.

## Vocabulary

| Term | In the code |
| --- | --- |
| Store | The Git repository at the Freeflow home (`FREEFLOW_HOME`, default `~/.freeflow`), marked by `store.json` with `kind: freeflow-store`; `isFreeflowStore`, `freeflowStoreOf` in `store.mjs`. Local, or cloud with the user's private remote. |
| Project | A folder `projects/<project>/` holding `rules/` and `tasks/`; a task in no project sits in the store's own `tasks/`. |
| Task folder | `task-NNN-<slug>/`: `record.md`, `history.md`, `decisions.md`, `sessions.md`, `sources/`, `delegations/`, `evidence/`, `scratch/`. Its ID is `<project>/task-NNN`, or `task-NNN` (`STORE_TASK_ID` in `projects5.mjs`). |
| Hold | The last line of a task's `sessions.md` that says `holding`: which session may write it. |
| Agreement, Slice, delegation | `A-NNN`, `S-NNN`, `D-NNN` (and `D-NNN.n` for a sub-worker), each with one History entry when it closes. |
| Context cycle | From a session's start or a compaction to the next compaction or the session's end. |
| Bundle | Everything recovery reads, in one text (`view bundle`): what Freeflow's compaction installs as the conversation. |
| Recovery budget | The words of memory the agent shapes that recovery may read, scaled by the square root of the context window (`budget5.mjs`). |
| Measure | One Slice's or delegation's use: context added, context cycles touched, working and wall-clock time, and billed tokens and list-price cost per model and effort (`measure5.mjs`). |

## How It Works

**The store.** `store init` makes a local store: `store.json`, `.gitignore` (`STORE_IGNORE`: `scratch/`, `evidence/**/raw/`, `local/`, `sessions/`, and `/events/` at the root only, so a task folder's `events/` is committed), `.gitattributes` (`STORE_ATTRIBUTES`: `history.md` and `sessions.md` merge by union), `rules/` with the default routing table in `rules/routing.md` (`DEFAULT_TABLE` in `routing5.mjs`, SPEC-010 T2), `projects/` and `local/`, the user's Git identity, and a first commit; the store's `tasks/` appears with its first task in no project. `store init --remote <url>` clones the user's private repository into the home instead, laying the store out when it is empty and joining it otherwise; a home that already holds an empty clone of that remote, as a cloud session has it, is used as it is (`isEmptyCloneOf`). A home that holds only Freeflow's own `sessions/` (Messaging's registry, a session summary written before the store) and `events/` (the event log) has no store yet: `session status` says the store is not there, and `store init` sets each beside the home while it lays out or clones the store, then puts it back, so neither a clone nor a failed init's clean-up touches it (`isEmptyHome`, `setSessionsAside`). `store remote --url` moves a local store's whole history into an empty remote. Every commit is the script's, authored as the user, with no trailers.

**Sync** (`syncStore` in `freeflow-store.mjs`). It commits what changed, scans the added lines for secrets (`SECRET_PATTERNS`), takes the remote's commits under the local ones, and pushes. A refused push takes the remote's commits and tries again; no network or no access (the fetch or the push fails) leaves the commits local and says so, and the next sync both takes the remote's commits and pushes. A conflict in any file other than the two union-merged ones aborts, keeps this store's version in place, committed and not pushed, puts the remote's copy under `local/conflicts/` (ignored, on this machine only), and stops until `store sync --resolved`. The harness layer runs `store sync --pull` at session start and `store sync` at a turn's end; holds, closes and checkpoints sync themselves.

**Tasks and holds** (`projects5.mjs`). `task create` makes a task folder in a project or in none and opens the hold; `task take`, `release` and `switch` append or close lines in `sessions.md`; a take refused because another session holds the task names that session and its last sync, and `--takeover` closes that hold as `taken over`. A harness layer closes the hold at the session's end with `task release --ended`, adding `--no-push` where the session's end leaves no time for the network (Codex's driver, which Codex gives at most 3 seconds): the release is committed here only (`syncStore` with `push: false`), `session status` then reports `changed`, and the next session start's `store sync` pushes it. It passes `task here --take-back` at its start: `takeBack` finds this session's last closed hold (holds of one session never overlap, so the later line within a task, or the later start across tasks, and where both minutes match the end is not taken as last) and, when it was closed as `ended` and is still that task's last line, opens the hold again, so a resumed session, a cloud session's above all, keeps its task. `checkpoint` refuses a task in the store that this session does not hold (`requireHold`), naming `task take`; a session with no ID, or a record outside a store, is not checked. The session comes from the environment (`sessionIdentity`: `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_REMOTE_SESSION_ID`, or `FREEFLOW_SESSION` and `FREEFLOW_HARNESS` from other harness layers). `task here` prints the session-start menu: the held task, then the open tasks of the project whose tasks name this repository's remote in Space (at most `MENU_TASKS`, 15), then tasks in no project; where no task names the folder's repository, as in a cloud session whose folder is the store itself, every open task in the store. With `--scan <folders>`, `task here` first remembers in `local/repositories.json` where each repository a task names is, from the Git checkouts at and directly inside those folders (`findRepositories`), so recovery resolves a task's repository pointers in a fresh container. With `--rules`, it adds after the menu the store's `rules/`, then those of the folder's project and of the held task's project, each whole and once (`sessionRules`), as the bundle prints them: what a harness layer gives a session at its start, so the rules hold before any task is taken. `session status` reports a session's summary and compaction request even with no store, since both live in the Freeflow home's `sessions/` folder and a session summary needs no store (P4); it adds `missing`: what keeps the session from a working store (a home `FREEFLOW_HOME` names with no store in it, an empty clone not laid out, a cloud session's store with no remote), each with its fix and whether the user or the agent makes it (`missingParts`), and `compact`: the request `checkpoint --compact` left in `sessions/<session>/compact.json`, which a harness layer answers once by compacting the session and marks done (P102). `task move` moves a folder with Git, giving it the destination's next number.

**The task's lifecycle** (`transitions5.mjs`). `agreement open | update | close`, `slice propose | start | start-direct | pause | resume | close | record`, and `checkpoint` each load and validate the task folder, build the new files, and publish them whole: `history.md` first, then `record.md`, then `decisions.md`, each only while it still holds the text the command read. A close writes exactly one History entry; a checkpoint rewrites In flight from its input, writes Space for the repository it runs in, and where that repository is on this machine in `local/repositories.json` (`rememberRepository`), adds the reading since the last one to the current Slice's `Measured:` line, sets "State as of", writes this session's event summary since it took the task into the task folder's `events/<session>.json` (a release does the same, `events5.mjs`), and syncs. Without a held task, `checkpoint --session` writes the session summary to `sessions/<session>/summary.md`.

**Views** (`views5.mjs`). `view recover` prints the opening line (the record is memory; the user's direction decides), the store's and the project's rules, `record.md`, the active decisions within their budget, the History index, the project index and the checks (the task folder's path, the budget, pointers that do not resolve, always Recovery lines that name no pointer, open delegations, the hold, unsynced commits, where each repository in Space stands). A relative pointer resolves from the task folder, then the work repository the command runs in, then each repository Space names at the path `local/repositories.json` holds for it (`resolvePointer` in `recover.mjs`, `spaceRepositories` in `budget5.mjs`), so a session started outside the work repository, as a cloud session started in its home folder is, still reads the skills and repository files the record names. `view bundle` adds every file the Recovery list's always lines name, whole or for the lines a line gives (numbered by file line), counted or not by the line's class, with their sizes, and the recovery line; `--fallback` is what Freeflow adds after the harness's own summary when the compaction came before the checkpoint, and `--session` a session summary's bundle, with the files its Recovery always lines name copied fresh after it. `view entry`, `view index` and `view full` read History and the raw record. A transcript is Claude Code's log or Pi's session file, known by its header line and read along its active branch (the path from the newest entry back through `parentId`), so a branch left with `/tree` is not read; a harness layer names it in `FREEFLOW_TRANSCRIPT`.

**Delegation** (`delegations5.mjs`). `delegate open` assigns `D-NNN`, writes `brief.md` from its template, makes a writing worker's worktree beside the repository on its own branch at the base, and writes the delegation's line in Current Work; `--parent` nests a sub-worker's folder inside its worker's and refuses a fourth level. With no task, `--scratch <folder>` in place of `--record` keeps the delegation under that folder's `delegations/` and records nothing; `check-return --scratch` checks it. `check-return` checks the return's headings and that its commits are on the brief's branch: a commit is a hex word in Identities with a digit, in lower or upper case, that no letter or digit touches (so `commit_abc1234d` is one), except inside an email address (whose domain ends in a label of letters and whose name is not itself a hex word), a UUID, a folder name between two slashes that is not a URL's git ref after `blob/`, `tree/`, `commit/`, `raw/` or `blame/`, and nothing else: a run next to a dot stays a commit, in either case and after `_` (`identityCommits`); the text cannot tell another repository's commit from this one's, so the coordinator names those with `--elsewhere <hash>=<owner/name>`, which check-return and close refuse when the return names no such missing commit, and close records on the entry's `Elsewhere` line; `close` records the outcome, the merge commit and the worker's measure in one History entry and removes the line. Delegations are apart from Slices: a Slice that needs one names it under `Waits on`. **Routing** (`routing5.mjs`, SPEC-010). Without `--agent`, `delegate open` takes the worker's model and effort from the routing table the user owns: the project's `projects/<project>/rules/routing.md`, then the store's `rules/routing.md`, rows in that order, the first that matches `--kind` (with `--tier`, as `security` for a `review (security tier)` row), `--settled` and `--check` winning; a cell that is not `any` matches only a value given. `frontier` is the coordinator's model, the newest request's in the transcript the harness layer names (`FREEFLOW_TRANSCRIPT`, P83), `cheap` the table's `Cheap:` line, and either stays the tier's name where it is not known. It prints the Route line after Space and writes `Route` (`<file> row <n>`, or `given`) on the brief's Agent line, with `Settled` and `Check` when they were given; it refuses before writing anything, with the reason, when there is no table, a table does not parse (the file and line), no row matches (the inputs), or the row says `Ask first: yes`, until `--agent` is given, and with `--agent` a table that does not parse only warns. `check-return` names the route and says what decides the return from Check; `close` copies Settled, Check and Route into History, and `--outcome "sent back"` requires `--reason brief | capability | scope`, kept as `Reason`. `--writes <glob>`, once per glob, puts a `May write:` line at the top of the brief's Scope, which the delegation gate reads ([Gates](gates.md)). `--session` (SPEC-009) hands the work to a separate session: the brief's Agent line says `Process: session` and the output prints the start command for Claude Code and Pi, whose prompt runs `delegate join` in the worker's session. `join` records the session as the brief's Handle and in the home's `sessions/<session>/delegation.json`; from then on that session holds no task, and `task take | create | switch`, `checkpoint --record | --session`, `slice`, `agreement`, `delegate close` and every other record write are refused ("this session works for D-NNN"); it may open subagent sub-workers (`--parent`), never another session. `checkpoint --delegation` rewrites a worker's `progress.md` (Done, Half done, Didn't work, Next, with `As of:`), and `view bundle --delegation` is what a worker session's compaction installs. Every delegation event is one line of the task folder's `channel.jsonl` (`lib/channel5.mjs`: `brief`, `amend`, `progress`, `return`, `blocked`, `sent-back`, `accepted`, `stopped`, `inform`; `from` is the session, with the agent ID for a subagent; the body redacted and cut to 300 characters); `delegate log` prints it and `--append` is a harness layer's `inform` or `blocked`. `check-return` warns when Left open has text but no `- <choice> -> <taken>[, technical]` line, and in a worker session leaves the record alone; `close --outcome accepted` adds each such line to `decisions.md` with the next free ID (`P<n> [default] … (from D-NNN)`, a technical one as a `T` item serving the plain item added last) and is refused when the list would not validate. `session status` adds `delegation` in a worker session, `waits` (the current Slice's open Waits on with what came back, from the log or `return.md`) and `claims` (this session's live claims). Claims (`lib/claims5.mjs`): `claim --paths`, `release`, and `delegate open --writes` append to the store's or project's `claims.jsonl`, paths kept relative to their repository (named as Space names it) so every checkout and worktree is covered; a claim lasts `--for` hours (`FREEFLOW_CLAIM_HOURS` from `delegation.claimHours`, else 4), is renewed at the session's `store sync` when less than half is left, each time by its latest line's own length (`until - ts`), and ends at release, its delegation's close (not a send-back), `task release --ended` or a worker's `release --ended` (which also logs that the session ended, so `delegate status` says to reassign). `channel.jsonl` and `claims.jsonl` merge by union; a store laid out before gets the lines at its next append.

**The gate state** (`gate-state5.mjs`). After each command that changes what the gates read (a take, release, switch or create, `task here --take-back`, an agreement's open or close, a Slice's start, pause, resume or close, a delegation's open or close) and after `agree`, the CLI writes `sessions/<session>/gates.json` again, derived from the record, through a temporary file and a rename; `session status` writes one where none exists, or again when a claims file in the store changed after it was written (`gatesStale`), so another session's new claim reaches this session's gates at its next turn end. `agree --outcome <text> [--exact-spec <reason>]` records the agreement of a session with no task there and as an `agreement` event line. How the drivers use it: [Gates](gates.md).

**Discussion and migration.** `discussion list` numbers the user's messages since the last checkpoint from a transcript reader per format (Claude Code's log, or a plain export); `discussion save` appends a block of chosen messages word for word, each with the agent's one line, and `drop` removes one (`discussion5.mjs`). `migrate` converts a Schema 4 record to a task folder, in place or into the store, keeping the old record whole as `sources/schema4-record.md`; with `--project`, a Schema 5 task kept in a repository's `.freeflow/tasks/` is copied into the store unchanged (`copyTaskIntoStore`, `migrate5.mjs`); a Schema 5 record written before the one Recovery list is converted in place (`migrateRecoveryHeadings`), keeping the old record as `sources/record-before-recovery.md`.

**Measurement and planning.** `slice start` takes a Slice's first reading and its prediction, each `checkpoint` adds what was used since, and `slice close` takes the last reading and copies `Predicted:` and `Measured:` into the History entry, with `Files:`, the files added, changed or renamed between the Slice's `Base` commit and HEAD (`filesChanged` in `transitions5.mjs`); `slice size` adds `Files:` to an older entry, dated. A reading walks the transcript the harness layer names (`FREEFLOW_TRANSCRIPT`, or `--transcript`) from the last reading on, reading the log's tail and growing it only until it reaches that time (`TAIL_STEPS`); `--used` gives a context figure where no transcript can be read. The prediction (`predictSlice` in `planner5.mjs`), for a Slice with a `Size`, is its size times the median per-file rate of the nearest of the task, its project and the store holding `MIN_MEASURED` (3) Slices with `Files` (`rateFrom`); otherwise the median of the nearest holding 3 complete measured Slices (each wider pool includes the narrower one's Slices). Its cost comes from that pool's Slices run mostly on the model and effort the Slice starts on, the transcript's newest request (`modelNow` in `measure5.mjs`), once 3 were, else from all of them (`costFrom`). Either is scaled by the geometric mean of actual over predicted of the Slices predicted the same way, from the first one, pulled toward 1 by `CORRECTION_PRIOR` (2) on-target Slices (`correctionFrom`), a cost only by predictions whose cost came from the model and effort their Slice ran on; a reading with no requests and no context is not measured. With fewer than 3 measured Slices in every pool, the Slice starts with no `Predicted:` line. `estimate` reports the context against the window and the notice point; `estimate --plan` predicts each Slice left (by its size where it has one), leads with the range in all and what it rests on, lays them across context cycles, adds the nearest pool's closed delegations by kind, check and model with how many were sent back and why (`outcomeRows`; `--store` the same for the whole store), `--json` gives the same as data for Discuss Work's `choices.mjs agreement --plan`, and `--project` and `--store` add up what was measured.

## Decisions

The P and T numbers name choices in the design that built this, task-004's Spec (`specs/memory-and-delegation.md` in that task's folder, with the user's words for each). The code came in by merge: the store in `ebf7c8e0` (hassan-mohiddin/freeflow#123), Schema 5's files, commands and views in `83454ea2` (#124), delegation in `9273f5e4` (#125), discussion, migration and the budget in `3f4f445e` (#126), Claude Code's mod in `992efbd4` (#127), Schema 5 as `init`'s default in `70afe225` (#128), and measurement and planning in `da8bc00c` (#129).

- **One Git repository for all task memory, local by default** (P1, P2, P58). Memory has to outlive sessions and containers; Git gives history, sync and conflict handling without a service. Local first, because nothing should leave the machine unless the user adds a remote; cloud is the same store plus a remote, so going cloud is one command. Rejected: memory in each code repository's ignored folder (lost with a cloud container, and invisible across repositories).
- **A cloud session's store is one of its repositories; Freeflow clones nothing** (P93, replacing P92). A cloud setup script cannot clone a private repository the session did not select (it fails with exit code 128), and a session starts with one repository, its code, so the agent attaches the store during the session on the user's word and Claude Code's mod takes it up at that turn's end; a session that works on the store alone starts with it. `session status`'s `missing` list says what is needed (P94). Rejected: the mod cloning the store from a URL the environment names (P92).
- **Projects are folders, holds are lines in the task** (P3, P44, T8). Membership is the folder tree and who holds a task lives in the task's own `sessions.md`, so no shared registry file can conflict between machines. Rejected: Pi's `registry.json`, which every change rewrote.
- **A session's end is not a release** (F36, the owner's choice, 2026-11-03). A hold closed by the session's end is `ended`, apart from `released`, and a resume of that session takes the task back: a cloud session ends when its container is reclaimed (seen on 2026-10-30, a release line written while no `task release` ran), so a resumed cloud session used to come back holding nothing. Only an end is taken back, never a release or a switch, and only while no other session took the task since; only `checkpoint` refuses without the hold, naming `task take`. Rejected: taking back any task whose last line is this session's, which would take back one released on purpose.
- **State rewritten, logs appended** (Spec principles 2 and 3). `record.md` holds what is true now, rewritten as the work moves; `history.md` and `sessions.md` only grow, merge by union, and are never edited, so a correction is appended inside its entry. Rejected: Schema 4's single record, whose History, Decisions and Checkpoints grew without limit.
- **The script makes every lifecycle change** (Spec principle 5). IDs, states, holds, closes and the checkpoint go through commands that validate before and after and publish whole files; the agent edits only meaning. A hand-made state change cannot be detected, so it is forbidden rather than checked.
- **A recovery budget that scales with the square root of the window, and only warns** (P32, P62). A larger window carries more memory, but slower than the window grows; the rules, the skills and the files Recovery's always, not counted lines name are read and never counted, so the agent cannot shrink what it must read. Recovery still reads everything it lists, because a must-read source skipped for room costs the next action more than its words.
- **One Recovery list, each line with its class** (A-005 P4 to P7, 2026-11-03). What recovery reads was four places (Defined by, Read on recovery, Read when, In flight's Carry line); it is one `### Recovery` section whose lines say `always`, `always, not counted` or `when <trigger>`, any file taking `(lines a–b)`. `recoveryItem` in `record5.mjs` parses a line, `recoveryEntries` in `recover.mjs` finds its pointers, and `sourceFiles` in `budget5.mjs` reads each file once, cut to its lines. `checkpoint --input` replaces the list after a `Recovery:` line, `Recovery: none` empties it, and without that line it is kept; the checkpoint prints each line's size and share of the budget, and names an `always, not counted` line the new list dropped. The old headings are refused by every command but `migrate`, which converts them in place (Defined by to `always, not counted`, Read on recovery and Carry to `always`, Read when to `when <trigger>`): no release wrote them, but development stores did, this task's among them (2026-11-03). Rejected: a next-cycle class that the checkpoint drops unless named again, since every list is decided again at each checkpoint anyway.
- **The checkpoint is the compaction's summary** (P59, P60, P63). In flight holds what sits below the record's grain, and the bundle is the record's own state, so Freeflow's compaction needs no summarizer request.
- **Readings only from the transcript the harness layer names** (P83, T30). Measurement writes into the record, so it never looks up a log by itself: a test inherits the session's environment, and a lookup would measure the session running it. `estimate` and `discussion list`, which only print, also find this Claude Code session's log by its ID.
- **Planning is deterministic** (P89). Medians, ranges and ratios over measured History entries; the correction divides by the uncorrected median, so corrections do not compound. Rejected: a fitted or probabilistic predictor, since a task holds too few Slices for one and its figures could not be traced.
- **Dollars at API list price from a dated table** (P86, T31). On a subscription the figure is what the work would cost through the API, not what is charged; `FREEFLOW_PRICES` replaces the table.

## Intended Behavior That Looks Wrong

- **A close that stops halfway leaves `history.md` ahead of `record.md`.** History is published first; running the same close again sees its entry and finishes the record without a second entry. Publishing the record first would lose the entry when the second write fails.
- **`history.md` and `sessions.md` can end up with both machines' lines in any order.** They merge by union on purpose: they only append, so keeping both sides is right, and a conflict there would stop work for nothing.
- **A record over its budget is still read whole.** The budget warns at `init`, `checkpoint` and recovery and trims nothing.
- **`checkpoint` writes Space only for the repository it runs in.** Another repository's line changes when a checkpoint runs there (or with `--repo`); the record never claims to know where a repository it cannot see stands.
- **A Slice measured with `--used` shows `working 0 min` and no cost.** Only a transcript gives requests' times and billing; the planner treats such a Slice's time and cost as unknown, never as zero.
- **`store init` refuses a home that holds Pi's `registry.json`.** Pi's former Task Memory kept its Schema 4 registry, projects and records there; laying a store over them would mix two layouts in one folder and strand those records, which `migrate` moves in from the original folder. The refusal (`task-memory-home`) asks for another folder, with `FREEFLOW_HOME` set to it for the sessions that use the store.
- **A moved task gets a new number, and its old ID names nothing.** Numbers are per folder and never reused; Git history keeps the old path.

## Surface

- Commands, all in `working-record.mjs` (`<group> <operation> --help` gives each one's options): `store init | remote | sync | status`; `events append | summary | show` (the event log: `append` for a harness layer); `init`, `validate`, `budget`, `estimate`; `agreement`, `slice`, `checkpoint`; `view recover | bundle | entry | index | full`; `task create | take | release | switch | here | search | remove | set-budget | set-state | move`; `project new | remove | list | show`; `delegate open | amend | status | check-return | close | join | log`; `checkpoint --delegation`; `claim`, `release`; `agree` (a session's agreement with no task, for the gates); `discussion list | save | drop`; `migrate`; `session status` (JSON for a harness layer).
- Environment: `FREEFLOW_HOME`; `FREEFLOW_CONTEXT_WINDOW` (the window the budget and `estimate` use, 200,000 when unset); `FREEFLOW_TRANSCRIPT` (the log measurement reads); `FREEFLOW_PRICES` (a price table file); `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_REMOTE_SESSION_ID`, `FREEFLOW_SESSION`, `FREEFLOW_HARNESS`, `FREEFLOW_RESUME` (the session and the way back to it).
- Exit codes: 0 published or nothing to change; 1 nothing written, with the reason; 2 the outcome is uncertain, so read `view full` before retrying.
- Text the agent reads: every view, the budget lines, `estimate`'s lines, the menu, the checks. The exact shape of every file is Track Work's `skills/track-work/references/working-record-format.md`.

## State

- **In the store, synced:** `store.json`, `.gitignore` and `.gitattributes`; `rules/`, each project's `rules/` and `tasks/`, the store's `tasks/`; in each task folder `record.md`, `history.md`, `decisions.md`, `sessions.md`, `sources/`, `delegations/`, `evidence/<slug>/README.md`, and `events/<session>.json`, each session's event summary.
- **In the store, this machine only** (ignored by `.gitignore`, so never committed or pushed): `local/` (where each repository is, sync state, conflicts), `sessions/<session>/` (the session summary, the mod's `cycle.json` and `delegations.json`, each driver's `capabilities.json`, the gate state `gates.json`), `events/<session>.jsonl` (the event log the drivers write, SPEC-006), each task's `scratch/` and `evidence/**/raw/`.
- **Nothing in memory survives a command:** each command reads the files, validates, writes, and exits. After a restart, a compaction or another machine, the files are the state.
- **Without a store,** a task folder lives in a repository's Git-ignored `.freeflow/tasks/`, and nothing syncs.

## Invariants

- A record is never written inside a Git repository that is not the store unless the path is ignored and untracked: `assertGitSafePath` in `store.mjs` refuses it with `unignored-path` or `tracked-path` and writes nothing (exit 1); inside the store, whose `store.json` marks its records as tracked on purpose, it allows any path (`store.test.mjs`, "the Git check accepts a record inside the store and still refuses one a code repository does not ignore").
- Every command publishes one complete valid result or nothing, and refuses to overwrite a file that changed since it read it (`publishAtomically`; `schema5.test.mjs`).
- Closing a Slice, agreement or delegation appends exactly one History entry (`schema5.test.mjs`, `delegations5.test.mjs`).
- A task has at most one holder, and a session holds at most one task (`projects5.test.mjs`).
- Nothing pushes without the secret scan, and only to the store's own remote (`store.test.mjs`).
- There is no fourth level of delegation (`delegations5.test.mjs`).
- Nothing in the store is written into a code repository; no test guards this absence.
- A test never measures the session running it: measurement reads only `FREEFLOW_TRANSCRIPT` or `--transcript`, and Track Work's suite runs with `FREEFLOW_TRANSCRIPT` cleared (`scripts/validation/with-symlinked-tmp.mjs`; `measure5.test.mjs`).
- A prediction never counts a Slice measured only partly, or a time or cost that was not read (`planner5.test.mjs`).

## Failure Behavior

- **Sync:** a moved remote is taken and the push retried; no network or no access commits locally, says so ("not pushed (…); the next store sync pushes it") and exits 0, and the next sync pushes; a secret stops the push with `secret-found`, naming the path, line and kind, and exits 1 (`store.test.mjs`, "a secret stops the push, named by path, line and kind, and a commit that held it never leaves"); a conflict stops with `sync-conflict`, both copies kept, and exits 1 until `store sync --resolved`. Work never waits on the network.
- **A command that fails validation** before its change writes nothing (exit 1); one whose write may have happened exits 2, and the agent reads `view full` before anything else.
- **A take on a held task** is refused, naming the holder and its last sync.
- **A reading that cannot be taken** (no transcript, no `--used`) leaves the Slice unmeasured; its History entry says `not measured`, and nothing waits on it. A worker whose log cannot be found is `not measured` too.
- **A planner pool with too few measured Slices** falls to the next pool; with none, `estimate --plan` asks for `--done` and plans at this context cycle's rate, and says so.
- **Another task's unreadable `history.md`** is skipped by the planner, never fatal to a Slice's start.

## Cost

- A reading reads the log's tail, 8 MB, then 64 MB, then the whole file, only until it reaches the previous reading's time; a long session's log is not read whole at each checkpoint.
- A Slice's start reads every task's `history.md` in its project and store to predict; this is file reads only, once per start.
- Commands run as separate processes outside any model request, so they add nothing to a request's path.

## Limits

- Schema 4 is read only by `migrate`, so a Pi user's records from Pi's former Task Memory move into the store with it before any other command can use them.
- The planner sizes every Slice the same, since Slices have no kind; delegations are grouped by kind, model and effort, and their sent-back rates by kind, check and model; the routing table does not learn from those rates (SPEC-010, out of Part 7).
- Prices go stale with the table's date until `FREEFLOW_PRICES` or a new table replaces them.
- The recovery budget's figures (10,000 words at 200,000 tokens, expanded half as large again) are starting points, not yet tuned by a continuity test.
