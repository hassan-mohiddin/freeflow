# Track Work

> **Covers:** `skills/track-work/`
> **Tests:** `.skill-eval/track-work/`
> **Verified at:** `6935f9f3` (2026-10-30)

For anyone changing Track Work: what it is meant to change, why it is shaped the way it is, and what the evidence shows. The method itself is in [the skill](../../skills/track-work/SKILL.md); this record holds the reasons it does not. How its script keeps the store and the task folder is [Freeflow store and Schema 5 tasks](../subsystems/freeflow-store.md). It was started with the Schema 5 rewrite (task-004's Phase 7.1), so it records that rewrite's reasons in full and older choices only where they still shape the text. Task-004's design, with every choice and the owner's words, is its Spec (`memory-and-delegation.md` in that task's folder); the choices are cited here by its IDs (P1 to P81, T1 to T28).

## Purpose

Track Work keeps one task's memory so a fresh context, after a compaction, in another session or on another machine, continues the work without the conversation that produced it. Its reader is the agent doing the work, and it is read whole at every recovery, beside Discuss Work and Execute Work. It changes the decisions where memory is made or used: which task a session works on, what goes where in the record, when and how to checkpoint, and how to recover.

## Behavioral Claim

- **Behavior it produces:** the session takes only the task the user's message points to and writes only that one; the agreement is written in the user's words; a Slice is recorded before its first effect, with one-line updates pointing to their evidence; the record stays within a recovery budget the agent knows before writing; at Freeflow's notice the agent works on to a safe point, rewrites Current Context and In flight, saves the discussion that shaped the work, runs `checkpoint` and ends its turn; after a compaction it continues from the bundle without reading it again, and elsewhere recovers through `view recover` and the sources it names.
- **Failure it prevents:** from task-001 and the four Schema 4 records (Spec section 1): records that grow and go stale (one Slice with 45 updates, a decision list of 7,600 words, recovery reading about 60,000), structure never used, Current Context patched instead of rewritten, records lost with a cloud container, and delegated work with no owner. From Pi's Task Memory evals: an agent with a record in focus did the record's next action instead of the user's request 3 times out of 3.
- **Earliest decision:** a session's first message, where Freeflow's menu lists the project's tasks and the user's words decide which one, if any, is taken.
- **Cues before the body is read:** its description; core's cycle, which names Track Work when work spans sessions, a compaction or a handoff; on Claude Code the mod's menu, its notice and the bundle's opening and recovery lines, all printed by the script.
- **Guaranteed context:** the description on every host. Where Freeflow's mod runs, the bundle carries the skill whole into every new compaction cycle, which is why its length matters.
- **Nearby cases it leaves alone:** a question or a short self-contained result, which needs no task; Pi's Task Memory, which keeps Schema 4 records through its own tool (the Schema 4 reference covers their shape); the decision list's method, which is Discuss Work's; delegation, which is Execute Work's reference.
- **When it stops steering:** at the task's close or release; between boundaries it asks for nothing ("update at boundaries, not after every step").

## Design

- **Schema 5 in the body, Schema 4 in a reference** (P70). Pi's Task Memory, its compaction summaries and its projects all rest on Schema 4 until Pi moves (step 3), and a record made before Schema 5 keeps working until the user has it converted (P73). The body describes one schema so a Claude Code or Codex agent reads no Schema 4 method; `references/schema-4.md` holds Schema 4's differences, its format and its projects and child records, moved from main whole so their wording carries over. Pi's task-memory and compaction skills link into it.
- **"Checkpoint" means only the save** (P71). Schema 4's Checkpoint, a selected stop on the route, became the agreement's `Back at` line, since both the user and the mod use "checkpoint" for the save before a compaction. Other skills still say "selected Checkpoint" until task-004's Slice 7.2 rewords them; the body's agreement section carries a one-line guard for that interval.
- **Rules kept few.** The Rules hold what is wrong in every case: the record is not authority (with Task Memory's sharper wording, that a record's next action is not a request, because of the 3-in-3 eval failure), taking and creating tasks only on the user's word, one writer, a Slice before effects, the script for lifecycle changes, the user's words for the agreement, recovery before action, and the two evidence rules. Choosing a task, the budget, the checkpoint and recovery are judgment with goals, since each has cases where the default is wrong.
- **The checkpoint as a numbered method.** It is the one sequence that must happen in order at a moment of pressure (the notice), so it is steps, with In flight's labels spelled as `checkpoint --input` takes them. The safe point is Pi's compaction skill's definition, kept because it worked there; the mod's notice uses the same words (P50).
- **What goes where as one table.** Schema 5 has more places than Schema 4 (agreement, decisions, Slice updates, delegations, Defined by, two kinds of read source, Space, In flight, discussion blocks), and the table is where an agent decides; Current Context's rule, that it changes only at a checkpoint (P5), follows it.
- **The store, projects and holds in the format reference** (2026-10-30, the owner's choice). They were a reference of their own; they are read with the task folder's shape often enough, and the two linked each other, so they merged. The file keeps its name, since Review Work and the developer docs link to it.
- **Choosing a task borrows Task Memory's request table, improved:** one row per thing the user's message can do, each with the script command, and the takeover, switch and close cases the hold adds (P40 to P44).
- **Harness-neutral, with the harness layer named once** (2026-10-30, P74). The script, the record and the checkpoint work on any harness; the text names "Freeflow's harness layer" for what calls the script at the right moments (the menu, the notice, the sync, and, where the harness allows it, Freeflow's own compaction), and Claude Code's mod only as today's example. The notice and the checkpoint are the core; Freeflow's own compaction is optional, since Codex's hooks, for one, can only stop a compaction.
- **A task may belong to no project** (2026-10-30, P76). It lives in the store's `tasks/` with ID `task-NNN`, and `task move` puts it into a project or takes it out, so a first task needs no project first. The agent asks one question, through the harness's question tool where it has one, with the project choice in it (P75), as Pi's Task Memory asks before creating a record, so the user always knows whether a task was made.
- **Compaction cycles as the measure of when memory is needed** (P77). "Spans several steps, compactions or sessions" left the agent no way to judge early; a compaction cycle, from a session's start or a compaction to the next compaction or the session's end, is defined once in the body, and a task is worth keeping when the work will outlast it. The harness layer's rows and notice name the compaction cycle, as Pi's status does.
- **"Compaction cycle" is Track Work's term, not core's** (P82, from Write Skill's Shared Terms procedure). Its readers are Track Work, Execute Work's context line and texts read where they appear (the notice, the rows, `estimate`'s output); Execute Work says it in plain words, and those texts name it in full, so no reader needs it before Track Work is read, and core pays nothing for it on every request. It is always written in full because core already calls agree, build, verify and review a cycle.
- **The context, measured** (P78, P80). `estimate` gives the context's use against the window and the notice point, and with the parts done and left, whether the rest fits or how many more cycles it needs, so the agent can tell whether work will outlast this cycle and plan where each cycle ends; the use comes from `--used` on any harness, or from the transcript where a reader knows its format. Where a harness layer runs, rows at 50%, 60% and 70% show the context passively; they are appended, so the prompt cache holds, and only at those marks, since every row stays in the conversation. Execute Work points to `estimate` when the route is set (P79).
- **What work used, measured by the script** (task-004's Spec, section 12, P83, P89, T29 to T31). `slice start` takes a Slice's first reading, each `checkpoint` adds what was used since the last one (so a Slice across compactions or sessions is counted whole), and `slice close` takes its last, into a `Measured:` line the History entry keeps ("not measured" when nothing could be read): the context it added per compaction cycle, its billed tokens and list-price cost by model and effort, and its working and wall-clock time (`lib/measure5.mjs`). Readings come from the transcript the harness layer names (`FREEFLOW_TRANSCRIPT`) or `--transcript`, else `--used`, never from a lookup of their own, so a test never reads the session that runs it. The harness layer names the transcript (on Claude Code the mod, at session start), and Track Work's suite runs with it cleared (`scripts/validation/with-symlinked-tmp.mjs`), since a test that inherited it measured the session running it and broke the pinned Slice outputs. `delegate close` measures a worker the same way from its own log beside the coordinator's transcript, found by the brief's Handle or the mod's map of workers, so its History entry needs no typed tokens or minutes (A).
- **Store setup lives in Setup Freeflow** (2026-10-30, P91, P72 changed). Track Work keeps only the trigger: a task always lives in the store, and where none exists the agent asks once, local only or local + cloud, then follows Setup Freeflow's `references/store-setup.md`, which also moves older records in (a repository's `.freeflow/tasks/` and Pi's Task Memory, through `migrate --project`) and ends with `session status`'s `missing` list empty. Setup is read once per user and machine, so it does not belong in a skill read on every task; Setup Freeflow already owned the store's setup section.
- **Freeflow compacts only on the agent's request** (2026-10-30, P102). `checkpoint --compact` is the one trigger; the notice reminds. First the mod compacted after any checkpoint that followed its notice (P51, T12), so a checkpoint taken for a pause or a switch after the notice also threw the conversation away, and the agent could not compact earlier at a natural boundary. Rejected: every checkpoint compacts (a pause or a switch would compact too).
- **Planning from measured cost** (P84 to P90). `slice start` also records a prediction (`Predicted:`): the median context, working time and cost of the nearest pool holding 3 measured Slices (the task, its project, the store; partly measured ones left out), each scaled by the median of actual over the uncorrected prediction from the nearest pool holding 3 predictions with their actual; History keeps it beside `Measured:`, so later predictions correct themselves (`lib/planner5.mjs`). `estimate --plan` lays the Slices left (Future Work, or a list given) across compaction cycles at that size, flags any bigger than one, lists those with no dependency between them, and prices delegations by kind, model and effort, and a fan-out; before 3 Slices are measured anywhere it plans at this compaction cycle's rate, from `--done`. Its `--json` feeds Discuss Work's agreement (`choices.mjs agreement --plan`): a Size line and, in Technical, the plan (P87). `estimate --project` and `--store` add up measured use (B). Medians, ranges and ratios only, no fitted model: a task holds too few Slices for one, and each figure can be traced to the entries it came from (rejected: a probabilistic predictor). Slices have no kind, so all of a task's Slices size its next ones (P88). Track Work owns the planner, since its figures are the record's and History's (P90); each skill that decides with them has one pointer where D-002's map found the decision: Execute Work's delegation reference beside its model table and at fan-outs, the worth-keeping paragraph and the rolling route here, Review Work's choice of tier, Evaluate Behavior and Research Work before a paid run, and Discuss Work's agreement; core has none, by P82's reasoning.
- **Recovery has two paths.** After Freeflow's compaction the bundle is the conversation, so the text says not to read it again; elsewhere `view recover` and the reads it lists. The fallback (a compaction before the checkpoint) gets its own line because there the record is behind the summary (P16).

## Rejected

- **Schema 5 only, with Pi's guidance left until step 3.** A Pi user who updated Freeflow would get Track Work text that no longer matched their records (P70).
- **Keeping "Checkpoint" for both meanings.** The save and the selected stop would share one word in the same skill, and the save is the one the notice uses (P71).
- **A Schema 5 record in the repository when no store exists.** Without a store nothing syncs and the mod stays off. First the repository's ignored folder was the fallback when the user declined the store; since P72 changed (2026-10-30), a task always lives in the store, set up local only or local + cloud, and a user who wants neither gets no task.
- **A separate reference for workers.** The delegation reference holds the worker's side (P36).

## Dropped

- **Accepting a plain bullet in Future Work.** The live run's agent wrote one and was refused; the refusal now names the shape instead, since Future Work holds only proposed Slices and the fixed budget counts them (T21).
- **Repeating Pi's "compact now" notice on Claude Code.** Claude's own compaction, with the bundle after its summary, is the backstop, and a second notice would turn the soft one into a hard one (P50).

## Open Questions

- Whether the body, now about 5,200 words, is short enough to pay at every recovery; the continuity test (Phase 8.3) and the friction log of Phase 8's conversion are the evidence that would settle it.
- Whether agents save discussion blocks when they matter and skip them when not; the live run's agent read them as required before the text said they are optional.
