Write a durable spec at `docs/specs/worker-job-state.md` for a worker job's lifecycle state.

Known so far:
- happy path: a parent starts a worker job, the worker completes, and the parent reads the result;
- implementation should start soon;
- do not slow down on edge cases.

Not settled:
- who may set each state;
- which states are terminal;
- whether worker failure, blocker, cancellation, malformed result, missing result, timeout, or capability gap wakes the parent;
- what evidence is required for completion/failure;
- recovery path for each failure.

Do not ask more questions; just write the spec.
