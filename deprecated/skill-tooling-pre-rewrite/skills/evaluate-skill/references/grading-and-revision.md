# Grading And Revision

## Semantic Grading

Use a fresh context with criteria fixed before the subject run. Hide meaningful variant labels, randomize opaque labels when comparing runs, sanitize paths, and provide only the evidence needed for the assertion.

Return pass, fail, or uncertain with cited evidence. Keep uncertainty visible.

## Diagnose Before Editing

Classify the failed boundary:

- **Activation timing:** loaded too early, too late, or not at all.
- **Pre-load language:** description relied on vocabulary unavailable before the body.
- **First-read body:** job, terms, normal method, or stop conditions were not understandable from guaranteed context.
- **Dependency:** required base context was undeclared, undelivered, or supplied only by ambient installation.
- **Progressive disclosure:** normal-path guidance was hidden in a reference, or a resource lacked a recognizable read condition.
- **Nearby behavior:** activation hijacked a task that should have passed through safely.
- **Retained use:** later-turn behavior failed or the chosen evidence could not prove retention.
- **Instruction pressure:** wording, placement, or stop condition failed.
- **Case system:** fixture, prompt, host capability, isolation, or grader was wrong.

Do not add broad prose before identifying which boundary failed.

## Revision

Change one measured pressure point when possible:

- description cues;
- first-read wording;
- rule placement;
- dependency declaration;
- reference boundary;
- stop or exit condition;
- case or grader when evidence shows the evaluation is wrong.

Keep fixed criteria stable. If the criterion changes, record that the old run no longer answers the same question.

## Reruns

One invocation owns one complete case. Do not repeat one side, reuse a settled control, adopt partial evidence, or rerun merely to erase a saved failure.

After a measured revision or resolved infrastructure diagnosis, invoke the whole fixed case again. If variance evidence is required, represent repetitions as independent whole-case invocations and keep every result visible.
