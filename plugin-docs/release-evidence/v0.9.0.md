# Freeflow v0.9.0 Release Evidence

## Status and identity

- **Status:** Prepared release; the `v0.9.0` tag, npm publication, GitHub Release, and consumer verification follow at the remote release boundary.
- **Package:** `@hassangameryt/freeflow`
- **Version:** `0.9.0`
- **Preparation date:** 2026-10-22
- **Source implementation checkpoint:** `c9afeedf11f3713c011cdba150dd54f6f7d5ff9f` (`Format the routing suite test`), on branch `refactor/core` after merging `main`; then the settings rows and live-verification change on branch `fix/settings-verification`, merged before the tag.
- **Release preparation:** `npm run release:prepare -- 0.9.0`
- **Version basis:** The user selected `0.9.0`. The release removes and merges skills and commands with no aliases (twenty-five skills become eleven), which a 0.x minor version marks. This records the selected target; it is not a universal compatibility claim.
- **Release notes:** [`CHANGELOG.md#090---2026-10-22`](../../CHANGELOG.md#090---2026-10-22)

The release keeps one canonical portable skill tree and one npm package across the supported host metadata and adapters. It does not claim that the restructured skills are behaviorally better: the before-and-after evaluations are planned after this release.

## Consumer-visible changes

- Eleven capability skills replace twenty-five: the Workflow skill's cycle is in the always-present core guidance, and Discuss Work, Execute Work, Deliver Work, Track Work and Write Docs absorb the skills merged into them. Removed skill names and commands have no aliases.
- Skills bring scripts that put a decision's facts in front of the agent (self-review, touch-map, choices, view recover, review-packet, the Deliver Work state and preflight scripts, plan-lint, artifact-check, and `skill-author compare`).
- On Pi, guidance notices push a skill's key lines at the tool call that needs them (`toolExecution.guidanceNotices`, on by default, with a Guidance notices row in `/freeflow settings`).
- On Pi, `/freeflow settings` has a Review row and a Reviewer model picker for the `review` setting, Runtime prompts and Skills rows with a switch per prompt and per skill, and every setting in all three scopes; a test fails when a config key Freeflow acts on lacks a row in any scope.
- The Working Method keeps tool output small on every host; the core guidance carries the agreement before building.
- Evaluate Behavior checks expectations and decisions when a definition loads, before any paid run, and refuses `host` inside a configuration's `runtime`.
- Pi 1.4.0 is the development and test host; Pi 0.99.1 or later is still supported.
