# Domain Skill Composition

Read this when specialized engineering guidance must operate inside the current Workflow owner.

Freeflow owns authority, ownership, route changes, evidence honesty, checkpoints, and Supported Exit. Domain guidance supplies specialized engineering method. It does not become another workflow or widen authority.

## Compose One Owner

For the current bounded activity:

1. keep one Freeflow owner;
2. add only the domain guidance required by the concrete technology, behavior, or risk;
3. use one primary implementation or diagnostic method at a time;
4. add Design for Depth only when direction is already design-bearing or evidence establishes structural pressure;
5. add independent specialist review only when it materially protects a selected boundary.

Prefer repository policy and current primary sources over generic examples. Do not load a handbook because one keyword appears.

## Preserve Boundaries

Domain guidance may own techniques for frontend, accessibility, browser tools, security, performance, databases, APIs, CI/CD, observability, cloud platforms, migration, release, or deployment.

It never overrides:

- user-owned product or risk decisions;
- repository instructions or accepted behavior;
- the authority envelope;
- source truth, failure contracts, or evidence requirements;
- the active owner's stop and return conditions.

When domain guidance conflicts with live source truth or accepted intent, return the conflict to Workflow. Use Decision Gate when resolving it changes user-owned behavior or material risk.

## Return

Return domain results and evidence to the same owner. A method change does not automatically change durable task state, accepted scope, or the current owner.

If no suitable domain guidance exists, inspect current primary sources and repository conventions. State expertise or environment limits rather than inventing a universal checklist.
