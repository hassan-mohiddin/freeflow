We have been brainstorming a Pi-based multi-agent workflow for Freeflow.

Settled so far:
- Separate agent contexts should be used only for real context boundaries.
- The main agent preserves the user-facing session and global continuity.
- Supporting evidence is stored outside the main conversation when it is large.
- Internal state can be JSON/JSONL, while model-visible input and results stay compact.

Still not deeply discussed:
- how role-specific context is loaded;
- which tools are active for each role and how enforcement works;
- exact result parsing and failure/timeout behavior;
- output-router boundaries;
- how worktrees enter execution later.

Should we write the spec now?
